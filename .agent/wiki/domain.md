# 业务领域知识

## 行业背景

### 初级农产品分装
本项目服务于滋补品商行的日常运营。根据《农产品质量安全法》，销售的农产品应当符合：
- 有包装或附加标识（标签）
- 标明品名、产地、生产者、生产日期等内容
- 农产品标识应当真实、清晰、规范

**本项目标签中的 "温馨提示" 文案是合规要求的重要部分，严禁随意修改。**

## 核心业务概念

### 规格ID (GoodsID / GGID)

系统的核心业务主键，来自上游电商平台（如小红书、淘宝等）。
- **格式**: 通常是 20+ 位的十六进制字符串，如 `6710cce9edb7ca0001035123`
- **特性**: 全局唯一，不变更（商品下架后也不重用）
- **使用**: 
  - goods.xlsx 规格ID列匹配
  - exempt_config.json 的 Key
  - 订单文件匹配字段

### SKU件数 vs 数量

不同电商平台导出的订单中，数量字段名不一致：
- **小红书**: `SKU件数`
- **其他平台**: `数量`

`config.json` 中 `num_field` 配置了候选列表，程序按顺序尝试匹配。

### 组合商品（子项）

一个商品在前台显示为 "红枣250g+桂圆250g 组合装"，但实际分装时需要打印两张独立标签。

- **配置方式**: goods.xlsx 「子项」列填写：`A#1,B#2`
- **展开逻辑**: 如果该组合商品订单数量是 3 份，则最终打印：
  - A 标签: 1 × 3 = 3 张
  - B 标签: 2 × 3 = 6 张

### 免打数量

某些商品是常备库存，包装标签已提前预打，不需要每次订单都重新打印。
- 示例：红枣每次来订单免打 5 份（已有库存标签）
- 存储：`exempt_config.json`，格式 `{规格ID: 免打数量}`

## 运营流程

### 日常运营一天

```
09:00  开机，启动 Python 主脚本（自动模式）
       ↓
       订单目录空，脚本每 10 秒轮询
       ↓
10:30  电商平台导出订单 xlsx，放入订单目录
       ↓
       脚本检测到新文件 → 匹配 goods → 生成标签 → 打印
       ↓
       打印机出 50mm×40mm 标签（可能几十张）
       ↓
       分装人员：按标签拼音顺序 → 找货 → 装袋 → 贴标签
       ↓
12:00  午休前：检查 bak 目录，确认上午订单都处理完成
       ↓
14:00  偶尔手动打单：
       打开 PrintTools.exe → TabSheet1 → 搜商品 → 点数量 → 保存
       ↓
18:00  下班：确认 application.lock 被清理，关闭脚本
```

## 异常场景处理

| 场景 | 正确处理方式 |
|------|-------------|
| 订单中的规格ID找不到 | **不要跳过**！提示 "SKU 名称没有在 GoodsConfig 中找到"，通知运营补录 goods.xlsx |
| 打印到一半缺纸 | 重新装纸后，使用 latest_print_file.xlsx 在 TabSheet2 里从断点重打 |
| 同一份订单打了两次 | 检查 bak 目录是否已存在同名文件，避免重复处理；必要时手动删除多余标签 |
| application.lock 残留 | 确认确实没有运行中的实例后，手动删除该文件，再重新启动 |
